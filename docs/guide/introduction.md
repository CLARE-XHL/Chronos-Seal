# 前言

Chronos Seal 是一套适用于 RPG Maker MV / MZ（Node.js 环境）的**无服务器本地化加密方案与安全套件**。

它的目标很简单：**让破解成本 > 游戏售价**，从经济学层面阻止批量盗版传播。


## 谁适合使用 Chronos Seal？

- 愿意以**时间换取安全**的 RM 开发者
- 需要确保套件**完整无后门**的 RM 作者
- 希望保护首发销售窗口期的独立游戏开发者

如果你只是想找一个“点一下就能加密”的工具，Chronos Seal 可能不适合你——它的使用门槛确实比图形化工具高一些。但如果你愿意跟着文档走一遍流程，它能提供的保护深度是图形化工具做不到的。


## Chronos Seal 的缺陷与门槛

### 本地加密的固有缺陷

Chronos Seal 可以挡住大部分小白，但**挡不住会 IDA 与二进制反编译的超级大佬**。

这是本地加密永远的缺陷：**密钥永远可以被 Patch**。

所以 Chronos Seal 无法做到完全防御，它只能：
- 挡住 90% 的脚本小子
- 拖慢剩下 10% 的破解者

> 关于 Chronos Seal 不能防 Patch 的问题：如果以后有人能攻克这个问题，密码学就可以被改写了。希望完全防 Patch 的，只能引用服务器动态验证或者上 Denuvo。

### 使用门槛

- 需要**注册 GitHub 账号**（用于 Actions 云端编译）
- 需要**安装 Node.js**（仅用于本地加密素材，玩家不需要）
- 目前**仅支持 Windows 平台**（Linux 没测过，但谁会拿 Linux 玩 RPG 呢？ Bush ～）
- 修改 `.node` 文件后，无法通过增量更新进行更新（需要把整个 `audio/` 和 `img/` 文件夹做成补丁再发布，更新包较大）
- 虽然使用 GitHub Actions 自动编译和 Windows 批处理自动加密，但整体流程仍然需要跟着文档走


## 不用 Chronos Seal，还有哪些替代工具？

个人建议可以去 **Project 1 论坛的「综合技术讨论区」** 看看，那边可能有门槛更低或更好操作的工具。

目前已知的同类工具包括：

### 一、虚拟文件系统（VFS）与资源打包类

- **白箱 RM 游戏素材加密工具（HakuBox VFS）**：图形化界面，支持增量补丁和 VFS 封装，将资源打包进专属 `.dat` 数据包，支持智能增量更新（对比 MD5 仅打包变更文件）。但加密方式仍停留在 JS 层，未下沉至原生层。

- **RPG Maker Binomorph**：将游戏资源打包为加密的 `.sga` 存档，提供专业级加密保护，支持 MV/MZ。Demo 版限制 400MB。

- **Enigma Virtual Box**：通用 Windows 应用程序虚拟化打包工具，可将整个游戏打包成单个 `.exe` 文件，在 RM 社区中被广泛使用。注意：免费版主要做打包和混淆，不提供真正的加密，且有报告称可能导致内存泄漏。

### 二、素材加密类

- **Encrypterator 3000**：专门加密 MV/MZ 图片和音频素材的工具。采用不同于 RM 内置的加密方式，使现有解密工具失效。开发者明确表示加密强度不高，主要目标是对抗现有解密工具。需配合配套插件使用。

- **POR_Asset encrypter + decoder**：RM 论坛插件，用于加密游戏素材，避免依赖 RM 默认加密。加密器在发布前使用一次即可移除。

### 三、代码与脚本保护类

- **RPG Maker Cook Tool Deluxe**：集大成的一站式游戏构建工具箱。提供 Halva Package 技术和深层加密保护资源与源代码、资源压缩（最多减少 70% 文件大小）、NW.js 源代码保护、元数据编辑器和 NW.js 管理器，兼容 Steam Deck。

- **JavaScript 混淆工具（Obfuscator.io / UglifyJS）**：利用 JS 混淆工具增加代码阅读和修改难度，属于低成本的基础防护手段。

### 四、商业加密方案

- **HakuBox VFS（付费版）**：白箱的付费版本，提供更完整的 VFS 封装和增量补丁能力，适合商业化项目。

- **Cooktool Delux**：论坛中提到的付费加密产品，功能覆盖资源加密、代码保护、构建优化等多个维度。

- **Enigma Virtual Box（付费版）**：付费解锁完整加密和虚拟化功能。


### 各方案对比一览

| 工具 | 类型 | 加密深度 | 使用门槛 | 收费 |
|------|------|----------|----------|------|
| Chronos Seal | 原生层加密 | C++ 层 | 中（需 GitHub + Node.js） | 免费（MIT） |
| 白箱 HakuBox VFS | VFS 封装 | JS 层 | 低（图形化） | 免费/付费 |
| Encrypterator 3000 | 素材加密 | JS 层 | 中 | 免费 |
| RPG Maker Binomorph | 资源打包 | 资源层 | 中 | Demo 限制 |
| Enigma Virtual Box | EXE 打包 | 打包层 | 低 | 免费/付费 |
| Cook Tool Deluxe | 综合保护 | 多层 | 中高 | 付费 |
| JS 混淆工具 | 代码混淆 | 代码层 | 低 | 免费/付费 |

### 如何选择？

- 如果你希望**低成本、快速上手**：白箱 VFS 或 JS 混淆可能是更合适的选择。
- 如果你希望**更高的安全性、愿意花时间配置**：Chronos Seal 的原生层加密方案提供了其他工具不具备的保护深度。
- 如果你需要**商业级综合保护**：Cook Tool Deluxe 或 Enigma Virtual Box 付费版可能是更好的选择。


## 如果你决定使用 Chronos Seal

如果你能接受上述缺陷和门槛，想要获得 Chronos Seal 的保护，请继续阅读 [快速开始](/guide/getting-started)。

如果你觉得门槛太高，或者不想折腾，那 Chronos Seal 可能不适合你——没关系，选择适合自己的工具才是最重要的。
