# 前言

Chronos Seal 是一套适用于 RPG Maker MV / MZ（Node.js 环境）的**无服务器本地化加密方案与安全套件**。

它的目标很简单：**让破解成本 > 游戏售价**，从经济学层面阻止批量盗版传播。


## 谁适合使用 Chronos Seal？

- 愿意以**时间换取安全**的 RM 开发者
- 需要确保套件**完整无后门**的 RM 作者
- 希望保护首发销售窗口期的独立游戏开发者

如果你只是想找一个“点一下就能加密”的工具，Chronos Seal 可能不适合你——它的使用门槛确实比图形化工具高一些。但如果你愿意跟着文档走一遍流程，它能提供的保护深度是图形化工具做不到的。


## Chronos Seal 的缺陷与门槛

### 本地加密的固有缺陷

Chronos Seal 可以挡住大部分小白，但**挡不住会 IDA 与二进制反编译的超级大佬**。

这是本地加密永远的缺陷：**密钥永远可以被 Patch**。

所以 Chronos Seal 无法做到完全防御，它只能：
- 挡住 90% 的脚本小子
- 拖慢剩下 10% 的破解者

> 关于 Chronos Seal 不能防 Patch 的问题：如果以后有人能攻克这个问题，密码学就可以被改写了。希望完全防 Patch 的，只能引用服务器动态验证或者上 Denuvo。

### 使用门槛

- 需要**注册 GitHub 账号**（用于 Actions 云端编译）
- 需要**安装 Node.js**（仅用于本地加密素材，玩家不需要）
- 目前**仅支持 Windows 平台**（Linux 没测过，但谁会拿 Linux 玩 RPG 呢？ Bush ～）
- 修改 `.node` 文件后，无法通过增量更新进行更新（需要把整个 `audio/` 和 `img/` 文件夹做成补丁再发布，更新包较大）
- 虽然使用 GitHub Actions 自动编译和 Windows 批处理自动加密，但整体流程仍然需要跟着文档走


## 不用 Chronos Seal，还有哪些替代工具？

个人建议可以去 **Project 1 论坛的「综合技术讨论区」** 看看，那边可能有门槛更低或更好操作的工具。

目前已知的同类工具包括：
- **白箱 RM 游戏素材加密工具（HakuBox VFS）**：图形化界面，支持增量补丁和 VFS 封装，但加密方式仍停留在 JS 层


## 如果你决定使用 Chronos Seal

如果你能接受上述缺陷和门槛，想要获得 Chronos Seal 的保护，请继续阅读 [快速开始](/guide/getting-started)。

如果你觉得门槛太高，或者不想折腾，那 Chronos Seal 可能不适合你——没关系，选择适合自己的工具才是最重要的。
