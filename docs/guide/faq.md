# 常见问题

以下是在使用 Chronos Seal 过程中可能遇到的常见问题及解决方法。

> 💡 **提示**：电脑端用户可以使用 `Ctrl + F`（Mac 用户 `Cmd + F`）快速搜索关键词，快速定位你遇到的问题。

## 插件相关

**Q: 插件管理器中没有显示 `auth_manager.js`？**

A: 请确认：
1. 文件是否放在 `js/plugins/` 目录（不是 `js/` 根目录）
2. 文件扩展名是否为 `.js`
3. 尝试重启 RPG Maker 编辑器

**Q: 游戏启动时报错 `AuthManager is not defined`？**

A: 说明插件未被正确加载。请检查：
1. `auth_manager.js` 是否已在插件管理器中启用
2. `decryptor.node` 是否已放置在游戏发行包根目录


## 加密相关

**Q: 双击 `encrypt_assets.bat` 后提示“未找到 Node.js”？**

A: 请先安装 Node.js（从 nodejs.org 下载 LTS 版本），安装时勾选“添加到 PATH”。

**Q: 提示“未找到 encrypt_config.json”？**

A: 请确认 `encrypt_config.json` 已放入发行包根目录（与 `www/` 同级），且文件名正确。

**Q: 加密过程中某个文件失败了怎么办？**

A: 加密脚本会在加密成功并校验通过后才删除原文，加密失败时原文保留。检查错误信息后可以重新运行 BAT。

**Q: V2.1 支持哪些素材格式？**

A: 目前支持 `.png`（图片）和 `.ogg`、`.m4a`（音频）。其他格式（如地图数据、JSON 文件）保持明文。

**Q: V2.1 和 V2.0 的加密格式兼容吗？**

A: 不兼容。V2.1 使用了新的素材加密格式（魔数 + HMAC），升级需要重新加密所有素材。

**Q: 修改游戏工程里的素材后，需要重新加密吗？**

A: 需要。每次修改素材后，重新运行 RPG Maker 编辑器部署，然后重新运行 `encrypt_assets.bat`。

**Q: 加密素材后，游戏会不会变卡？**

A: 不会。解密运算量极小（XOR + HMAC 校验），且引擎加载素材本身已是同步阻塞的，解密开销可以忽略。


## 游戏启动相关

**Q: 加密后游戏无法启动怎么办？**

A: 请确认：
1. `decryptor.node` 已放入发行包根目录
2. `index.html` 已替换为 Chronos Seal 版本
3. `auth_manager.js` 已放入 `www/js/plugins/` 目录并在插件管理器中启用
4. 所有素材已正确加密（`.enc` 文件存在）

**Q: 游戏运行时报错“文件魔数校验失败”？**

A: 说明加密文件格式不正确。请确认使用的是 Chronos Seal V2.1 版本的加密脚本，且 `encrypt_config.json` 与 `decryptor.node` 来自同一次云端编译。

**Q: 游戏运行时提示 `decryptor.node` 加载失败？**

A: 检查：
1. `decryptor.node` 是否在发行包根目录
2. `auth_manager.js` 是否在 `js/plugins/` 目录
3. 插件是否在 RPG Maker 插件管理器中启用


## 看门狗相关

**Q: 看门狗在正常游戏过程中触发告警？**

A: 可能是心跳间隔设置过长，或者游戏主线程在执行耗时操作时卡住。建议将心跳公共事件的间隔调整为 **3 帧**（约 0.05 秒），确保在 10 秒超时阈值前能及时发送心跳。

**Q: 不需要看门狗功能可以关掉吗？**

A: 可以。在公共事件中注释或删除 `AuthManager.startWatchdog()` 和 `AuthManager.heartbeatReply()` 的调用即可。但不建议在生产环境中关闭。


## 云端编译相关

**Q: 为什么必须设私有仓库？**

A: Actions 日志中可能包含密钥信息。私有仓库的日志只有你自己能看到，公开仓库的日志全世界都能看。

**Q: 编译失败了怎么办？**

A: 检查以下几点：
1. `system.json` 是否在仓库根目录（不是子文件夹）
2. `system.json` 是否是合法的 JSON 格式
3. 检查 Actions 日志中的错误信息

**Q: 我可以多次运行 Actions 吗？**

A: 可以。每次运行都会生成新的密钥和 `.node` 文件。旧的 `.node` 文件将无法解密新加密的素材。

**Q: V2.1 还需要上传 `config.h` 吗？**

A: 不需要。V2.1 改用 `-D` 宏在编译时传入所有参数，`config.h` 已移除。

**Q: V2.1 还需要运行 `ChronosScan.bat` 吗？**

A: 不需要。V2.1 已移除检查点功能，不再需要扫描地图。


## 配置相关

**Q: 时间炸弹截止日期怎么设置？**

A: 在触发 GitHub Actions 时填写 `截止日期` 参数，格式为 `YYYY-MM-DD`。留空则永不过期。

**Q: 游戏版本号填什么？**

A: 填写你游戏当前的版本号（如 `1.0.0`）。每次更新游戏时，建议同步更新版本号，因为版本号是密钥派生的输入之一。


## 网络相关

**Q: GitHub 访问不稳定怎么办？**

A: 请参考 [网络环境](/guide/network) 章节，使用 Watt Toolkit 等工具优化网络连接。

**Q: 下载 Release 包速度很慢？**

A: 可以尝试使用 Watt Toolkit 加速，或者使用代理工具。也可以让朋友下载后通过网盘分享给你。


## 其他

**Q: V2.1 还需要输入 RPG Maker 的素材加密密钥吗？**

A: 不需要。V2.1 不再依赖 RM 自带的素材加密，部署时直接跳过即可。

**Q: 如果加密失败，原始素材会被删除吗？**

A: 不会。加密脚本会在加密成功并校验通过后才删除原文，加密失败时原文保留。

**Q: 为什么时间炸弹检测到了时钟回拨，游戏还能运行？**

A: Chronos Seal 采用“只告警不误杀”的设计原则。时钟回拨可能是 NTP 校时或 Windows 休眠导致的，不应该直接封杀正版用户。

**Q: `author_secret.txt` 丢了怎么办？**

A: 无法恢复。`author_secret.txt` 是游戏加密的唯一凭证，丢失后无法恢复。请务必在收到文件后立即备份到至少两个不同的物理设备。没有该文件你无法重新生成匹配旧游戏的密钥，只能在新版本中重新全套加密素材后发布更新。

**Q: 我可以把 Chronos Seal 集成到我的商业游戏中吗？**

A: 可以。Chronos Seal 采用 MIT 许可证，允许在商业项目中使用，但**严禁直接售卖 Chronos Seal 本体**。

**Q: 如果遇到无法解决的问题怎么办？**

A: 请前往 [如何反馈](/guide/feedback) 提交 Issue。
